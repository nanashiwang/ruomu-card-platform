# Agent Note: 发票先上传再通过发送

Status: implemented

## Problem

后台待审核申请没有上传入口，操作人员需先通过、再上传、再发送，容易遗漏邮件交付。

## Decision

待审核允许保存或替换私有 PDF 草稿，用户不能下载。上传后点击申请通过并发送，前端依次调用已有 review 和 send 接口，分别保持审核与发送权限。审核通过有草稿时进入 issued；旧 approved 无文件仍允许上传。驳回清除草稿，重提不复用旧文件。邮件失败保留 issued 文件与可重试状态，刷新失败不声称发送成功。

已检查商品能力图、发票服务、后台页面、用户下载和角色权限。与[原发票决定](2026-11-10-order-invoices.md)部分重叠，本篇替代后台操作次序，保留原隐私和发送占用规则；运营申请通知决定无变化。

## Alternatives considered

仅在浏览器选文件后依次审核、上传、发送改动少，但文件未保存时先审核，上传失败会留下无附件已通过状态。新增合并接口可集中调度，但要引入额外权限并处理 SMTP 无法参与数据库事务的问题；复用已有接口与持久状态恢复。

## Consequences

`./scripts/build.sh` 通过全量 Go 测试、API 编译、前后台类型检查与构建。新增测试覆盖草稿管理员下载/用户禁止下载、替换、审核发布、不可覆盖已开票文件、正确收件人与附件、SMTP 失败重试与已发送幂等、驳回清空和退款限制。原生命周期测试调整为允许待审核上传，保留旧先审核后上传路径验证。

Playwright 对真实 Vue 页面和模拟 API 验证待审核筛选、无附件禁止通过、上传后通过并发送、首次发送失败、列表过滤掉已开票后仍保留详情重试、重试成功和 390px 无横向溢出。未向真实客户发邮件。

审核与发信是两个请求，浏览器中断可能留下已开票待发送，后台显式提供发送按钮。SMTP 成功仅代表服务器接受。无 schema 迁移；既有单独权限仍分别控制上传、审核、发送，合并按钮需要审核与发送权限。
