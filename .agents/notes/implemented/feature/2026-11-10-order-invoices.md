# Agent Note: 订单发票申请、人工审核与邮件交付

Status: implemented

## Problem

用户能够下单并接收订单邮件，但缺少发票申请、审核、文件与发送结果。现有公开上传目录不适合包含抬头和税号的发票。

## Decision

复用订单身份与租户校验、后台 RBAC 和 SMTP。个人中心 `/me` 在概览顶部和共用导航展示“申请发票”，进入登录保护的 `/me/invoices`，复用 OrdersPanel 的订单查询、筛选、分页，展开 OrderInvoice 直接申请、查状态和下载。保留所有订单并提示资格限制，避免仅过滤当前页导致漏单；不增加独立订单 API。登录用户也可在 classic/vault 订单详情对已付款、未退款的主订单申请；一订单一申请，驳回后更新原记录重提。金额和币种由服务端订单生成，审核和上传重新核对。管理员审核、上传 PDF、确认发送或失败重试；业务开票状态与邮件状态独立。PDF 最多 5 MiB，保存在数据库私有列，普通查询不读文件，仅授权下载可取出。数据库原子条件更新保护并发审批、上传和发送；发送占用超时可恢复，但 SMTP 与数据库无法保证 exactly-once，超时重试可能重复邮件。

第一版不接税务接口、不生成发票、不跨订单合并、不提供游客申请。游客已有订单查询不受影响；游客开票需要额外身份验证设计。分销站沿用订单租户隔离。

## Existing capabilities and note audit

已核查 FEATURE_MAP、两套订单详情、订单租户查询、后台路由权限、SMTP 附件发送及发布流程。活跃笔记中没有发票所有者；翻译与首页笔记无关，[容器发布笔记](../process/2026-10-17-container-release.md)持有数据库无变化门禁，本功能需单独增量建表迁移，不能绕过该门禁。

## Alternatives considered

- 仅增加跳转订单列表的按钮最省改动，但用户仍需进入详情寻找表单；新增个人中心发票模式复用列表与表单，减少入口层级，代价是 OrdersPanel 多一个展示模式。

- 接入自动开票可减少人工操作并自动回传票据，但需要供应商与开票主体配置，超出已确认的人工开票方案。
- 使用公共媒体上传实现便捷，但静态路径绕过订单所有权校验；采用认证下载。
- 磁盘私有文件减少数据库体积，但需要额外持久卷、原子写入和备份一致性；第一版以限额 PDF 换取事务与备份一致性，后续大规模文件需迁移对象存储。

## Verification

个人中心入口调整通过用户端类型检查和生产构建、笔记检查；Playwright 使用模拟 API 验证 classic/vault 概览入口 → 发票订单列表 → 展开表单 → 提交后显示待审核，390px 页面无横向溢出。订单读取失败显示错误及刷新重试。未操作生产订单或部署服务器。


`./scripts/build.sh` 通过全量 Go 测试、API 编译、user/admin 类型检查与构建；部署脚本 53 项测试通过。新增测试覆盖用户/租户隔离、金额/退款限制、重复与并发申请审核、驳回重提、PDF 限额/JSON 隐私/认证下载、PDF MIME 二进制保真、SMTP 失败重试/并发发送/过期占用恢复、角色矩阵和增量迁移重复执行。使用本机模拟 SMTP 服务器验证真实网络发送及成功写回，没有给外部客户发送测试邮件。

Playwright 对真实前端与模拟 API 验证 classic 提交、后台驳回、vault 企业重提、审核、上传、邮件失败重试与用户下载；390px 手机界面无横向溢出。模拟前端接口与本机 SMTP 验证不能证明生产邮箱最终投递。PostgreSQL 使用微秒发送占用时间匹配，未在真实 PostgreSQL 环境演练。

发布保持现有 card-完整 SHA 流程，不增加第二套版本号；`migrate-invoices --apply` 仅迁移发票表及财务发票权限。生产升级按 `docs/10-订单发票.md` 独立迁移后再经过原无变化启动门禁，本次不操作生产数据。

## Consequences

复用订单、权限与邮件配置，两个模板共用申请组件；以数据库事务与一致性备份换取 PDF 带来的数据库增长。发票已发送后发生退款需人工处理票据，系统不自动红冲。新增表需独立迁移后才能使用现有禁止隐式数据库变化的生产部署工具。申请驳回后重用原行；上传后的文件不可覆盖，需要上传前人工核对。发送超时结果可能不确定，重试可能产生重复邮件；页面明确显示发送状态和重试入口。
