# Agent Note: 按用户设置商品专属价格

Status: implemented

## Problem

会员等级价只能为一组用户定价，运营不能给同一等级的不同客户约定不同商品单价。价格必须贯穿商品展示、购物车、预览和下单，不能只在后台保存配置。

## Decision

新增用户、商品、规格唯一的专属价格，规格 0 表示商品统一价，具体规格优先。后台用户详情维护，价格为正数且最多两位小数，校验用户、商品和规格归属。命中后作为固定成交单价，跳过活动、批发和会员折扣，优惠券继续按原流程处理。删除恢复原价规则。仅主站登录用户生效，分销站保留自己的价格体系；用户身份来自 JWT，不接受查询参数。登录商品接口与公开接口分离并禁止共享缓存，公开响应不含任何用户价格记录。

## Existing capabilities and note audit

检查了 FEATURE_MAP、会员等级价仓库、商品 DTO、用户详情、订单公共 buildOrderResult、购物车和 RBAC。活跃笔记中没有定价决定；发布与工作流笔记不持有本功能。沿用 Go API 和两套 Vue 前端；数据库自动迁移新增表，不修改历史订单。

## Alternatives considered

- 每个用户创建一个会员等级可以复用等级价，但破坏原会员权益和自动升级机制，还会暴露大量虚假等级。
- 专属价作为基础价再叠加现有折扣能少改条件，但运营无法明确约定最终单价，因此使用固定价格并明确优惠券边界。
- 仅下单时改价会让目录、详情、购物车与付款不一致，因此统一接入这些入口。

## Verification

后端全量 `go test -p 2 -timeout 8m ./...` 通过；新增测试覆盖用户隔离、规格优先、原子覆盖与删除重建、无等级用户、非法金额和跨商品规格、存储失败阻止计价、运营/只读等角色边界，以及预览与公共下单构建逻辑一致。handler 测试覆盖金额 JSON 类型、用户不存在、配置增删和私有缓存头；分销展示和购物车不采用主站用户价。

三端构建通过，部署脚本 53 项测试通过。Playwright 在实际 Vue 页面和模拟 API 上验证后台商品价/规格价保存、更新不重复、删除回退、只读账号不显示写入控件、390px 布局，以及登录前台请求携带认证并显示 125 元固定价、跳过 20 元会员价及 60 元批发价。浏览器测试使用模拟数据，不代表已在生产购买。

发布沿用 main 推送触发的 GitHub Actions，版本号 `card-完整提交 SHA`；不改生产数据，不自动更新生产容器。

## Consequences

独立配置满足同会员等级的客户差异定价，复用现有商品、购物车和订单入口；代价是额外价格查询及需要维护客户协议价。新增表随现有 AutoMigrate 创建；独立唯一索引与原子 upsert 保证重复保存不生成重复记录。专属价允许高于公开价，页面需显示实际单价；历史订单快照不追溯更改。配置规模按单用户管理，不加入批量导入或有效期功能。商品列表对活跃规格逐个解析价格，当前沿用分页规模；超大规格目录需后续用实际性能数据评估批量读取。
